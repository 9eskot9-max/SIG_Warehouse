- **Operations:** family membership drives shared PM/co Workbench tasks. A Project-specific team replaces the family team for that Project. Family defaults apply until exceptions are configured. An active, uniquely linked Employee readable by the User is required. Actual-user roles, User Permissions, linked-record access and isolation are NOT VERIFIED.
- **Cycle dashboard and closure:** Site Cycles has a separate cross-project role-gated dashboard using Frappe record permissions, so family Workbench filtering does not establish dashboard isolation. Manual close separately requires permissions and still checks a legacy name roster; changed names or newly configured staff may be unable to close. Evidence-driven progression remains separate. Review the intended dashboard audience and retire or deliberately retain the name dependency.
- **Planner:** flexible team identity and dated leader history are implemented; the initial matching legacy leader retains earlier position history. Project coverage is reference data; DC and Incident modes remain distinct, and Planner may assign any eligible site. A team with zero or multiple active leaders, or an inactive leader, is omitted by the adapter. Live leader changes, continuity and permissions remain NOT TESTED.
- **Petty cash:** routing is a separate published revision with System Manager authorization, proposal scope preview, hash check and recoverable history. Inherit resolves the family default when the routing proposal is published; changing a family default alone does not automatically republish the stored employee reviewer group. PC reviewer/Finance workflows, overrides and restoration remain NOT TESTED with actual users. Do not infer exact ERP Projects from PC groups.

PR #89 did not change the RV80 contract; no BAS edit is indicated for this People cutover. The actual workbook's imported modules, sync, CSV/TCN execution, historical Project links, and new PO setup have not been verified end to end.
