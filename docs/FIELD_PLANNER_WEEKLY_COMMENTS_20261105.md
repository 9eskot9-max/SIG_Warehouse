# Field Planner weekly comments — local implementation

Status: the original employee-private stream was deployed in PR #93. A separate shared-by-family stream is now prepared locally on `codex/field-planner-comments-operations`; it is not merged or deployed and has not been accepted by actual users. This is separate from the older `SIG PM Weekly Review` job and its three outgoing messages. Nothing sends WhatsApp messages or changes that job's settings.

- The Planner shows three fields for the signed-in employee: last week summary, this week plan, and comment on the ERP plan.
- A new period starts Sunday at 19:00 Asia/Riyadh. Periods are computed server-side, independently of the browser's time zone. Prior saved periods remain in the employee's history; no records are deleted. The page warns rather than discarding unsaved text at the cutoff.
- Each record is bound to the unique active Employee linked to the authenticated User. The endpoint requires the existing Projects Manager or System Manager role, Planner access and Employee read access. Employees cannot choose another employee in the request; an administrator can read records through the restricted DocType. Confirm the actual PMs hold the required roles before release; no role is granted here. Concurrent saves use a lock and a modified-time check; a request from an expired period is rejected.
- Long cycle storage names are retained in links and identifiers, while the Planner's visible scope labels and map tooltips show the PO and date. DC and Incident planning logic is unchanged.
- The table and service need a normal app migration. No Planner role, Employee permission, User Permission or role profile is changed here. Verify actual PM identities, Employee-link visibility and read/write boundaries in fresh sessions after an owner-authorized deployment. Check other Planner audiences and route rendering; record acceptance as PASS / FAIL / NOT TESTED.
- The new comments are not automatically submitted to PMs' managers, sent by WhatsApp, used to change the plan, or converted into site decisions. The user has not specified a manager review screen or notification workflow.

## Shared family comments — local review, 7 November 2026

- The Field Planner now uses a distinct shared weekly stream keyed by canonical project family and Sunday 19:00 Riyadh period. Its selector is sourced from `sig_warehouse.sig_warehouse.project_family.DISPLAY_LABELS`: Capex, Incident, and Colocation (shown as **5G / Colocation**). It does not infer a family from the commenter or a Project.
- Each signed-in user in the existing Field Planner audience can read and save the selected family's current and prior shared periods, provided the existing `_require_access()` gate succeeds (planner role plus `SIG Site Cycle` read). The Page roles remain System Manager, Projects Manager, Projects User, and SIG Field Ops. No new role, Page, Workspace, User Permission, or broad DocType permission is added. The new DocType's direct read/report permission remains System Manager only; writes happen through the guarded endpoint. The old personal endpoint and DocType remain unchanged.
- Source permission baseline reviewed before this change: the original comment endpoint added Projects Manager/System Manager and Employee-read/unique-active-Employee checks on top of `_require_access()`; `SIG Planner Weekly Comment` grants direct read/report only to System Manager. Field Planner Page roles and linked `SIG Site Cycle` read permission are unchanged. The new runtime audience is the same as the Page's existing four roles, subject to that Site Cycle read gate. No unrelated permission writer was changed.
- Existing employee-private records and their histories are retained in `SIG Planner Weekly Comment` and are not copied into a family. The new shared history starts separately. No historical identity-to-family mapping was made because one commenter may serve more than one family and the existing records do not identify a target family.
- The comments panel is moved below the map and immediately above `.sig-planner-tabs`. The Save comments button now has a clear green treatment and check icon. Unsaved text locks the family selector; saves retain the period check, family check, length limit, cache lock and modified-time conflict check.
- Focused tests: `sig_warehouse/tests/test_planner_weekly_comments.py` — **11 passed**; JavaScript syntax, Python compilation, DocType JSON parse, and `git diff --check` — **PASS**. These are local checks, not a Frappe migration or browser test.
- Live migration, route rendering, fresh-session access for Projects User/Projects Manager/SIG Field Ops/System Manager, denial for users outside the page audience, and linked Site Cycle access are **NOT TESTED**.
